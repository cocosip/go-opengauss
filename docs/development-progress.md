- [ ] **F04 Standard SQL.** Reproduce the official DDL, prepared insert loop, update, scalar function, transaction and JSONB examples. Check isolation, multiple results, RowsAffected, unsupported LastInsertId and INSERT RETURNING.
  Partial, 2026-11-25 (commits 5ae1c7a, 8e79bdb, 69a060b). A parameterless statement executed directly on the connection may carry several statements: `QueryContext` returns the rows of the first statement that produces them, statements without rows are skipped, and `NextResultSet` advances through the remaining sets with their own columns and OIDs, even when the current set still has unread rows (they are consumed and discarded); an error in a later statement keeps its SQLSTATE, an empty statement is skipped, and closing the rows drains the remaining sets so the session is reused. JSONB and the official example suite were the remaining items; both are now covered offline: the official Go guide's common operations are reproduced in `examples_test.go` — the multi-line `CREATE TABLE`, the prepared insert loop, the prepared update whose `UPDATE n` tag feeds `RowsAffected`, the scalar function call with three integer arguments, the manual transaction, and the JSONB insert, select and `RETURNING` round trip (the guide has no `RETURNING` step; it checks the generated-key route) — and `TestLiveOfficialExamples` runs the same steps plus row iteration and rollback checks against a live server when `OPENGAUSS_DSN` is set; JSONB stays text, so the example decodes it with `encoding/json` at the caller. - [ ] **F05 Types.** Round-trip parameters and values. Check ColumnTypes, B booleans, precision and negative scale, NULL/empty values, arrays, UUID, BLOB, timezones and unknown OIDs. Record multidimensional array limits.
  Partial, 2026-11-25 (commits 496ac60, 8e7e7a3). Results are read in the server's text format and decoded by type OID: bool becomes bool (both t/f and B-mode 1/0), int2/int4/int8/oid become int64, float4/float8 become float64 (including NaN and Infinity), bytea becomes []byte in both the hex and the legacy escape text form, date/timestamp/timestamptz become time.Time, and everything else, including numeric, JSON, UUID, arrays, enums, domains and unknown OIDs, stays the exact server text. `ColumnTypes()` reports the database type name and the Go scan type per column, plus the declared length of a varchar/char/nvarchar2/bit/varbit column (an openGauss character-semantic length such as `varchar(10 char)` is masked to 10) and the precision and scale of a numeric column (a negative scale, which A-compatibility mode on 6.0+ can declare, is preserved; the server's "precision without scale" sentinel reports no scale); an unconstrained type reports no value and nullability stays unknown because it needs a catalog lookup. A result column in binary format is refused instead of being decoded as text. Values that are not in the canonical shape (infinity, BC dates, an undecodable bytea escape, out-of-range clock or offset fields) fall back to text so nothing is guessed. Parameters are text: `[]byte` passes through unchanged, so a bytea parameter must already be written as `\x` hex, and bool is sent as 1/0, which the native and B-mode parsers both accept. `numeric` stays text to keep precision. Still open: B-mode BLOB/RAW OIDs (86, 88) are not distinguished from text and are returned as the server's hex text, arrays are not expanded into Go slices and their multidimensional limits are unrecorded, and the value set has not been exercised against a live server.
- [ ] **F06 Cancellation and reuse.** Cancel a running query, close rows early, inspect SQLSTATE, reuse a synchronized connection and confirm no duplicate write on lost COMMIT response.
  Partial, 2026-11-25 (commits 5ae1c7a, 58d00f4). Context deadlines and cancellation interrupt startup and row streaming, early Rows.Close resynchronizes the session, SQLSTATE survives errors, a failed transaction reports the server's ROLLBACK tag instead of a false commit, and a lost COMMIT response discards the connection. A protocol CancelRequest is now sent on a separate connection to the exact peer address of the session, carrying that backend's process ID and secret key. The driver waits for the postmaster to close the cancel connection, as libpq does, before the session may run another statement, so a processed cancellation cannot abort the next one; when that acknowledgement or the statement's answer does not arrive within one second the operation fails with the caller's context error and the session is discarded. Any operation interrupted by its context also discards the session, because its reply was never consumed and a pending result must not leak into the next user of the pooled connection. `ExecContext` reports the server's SQLSTATE 57014 deterministically, while `QueryContext` callers may instead observe database/sql's own context error because database/sql reports the context error it observed before the driver's result. Startup cancellation still interrupts the handshake immediately because no backend key exists yet. Stmt.Close/Commit/Rollback still run without a caller deadline, and neither cancellation path has been exercised against a live server.
- [ ] **F07 High availability.** Test all six target_session_attrs values. Verify actual role when the first address is a primary and a standby exists, and when only a primary remains. Cover strict-role failure, timeout, failover and reconnect during an upgrade.
  Partial, 2026-11-25 (commit 07e192d). `target_session_attrs` is implemented for all six libpq values through the DSN, a URL query and `PGTARGETSESSIONATTRS`, with DSN precedence. After authentication the driver reads the session's recovery and read-only state in one query (`SELECT pg_is_in_recovery(), current_setting('transaction_read_only')`), inside the same per-target `connect_timeout` window, and rejects a target whose observed state does not match; `prefer-standby` keeps the first acceptable server as a fallback when no standby is among the endpoints; this differs from libpq's two-pass re-dial but yields the same "standby if any, otherwise any" result, and an authentication failure on any endpoint aborts the whole attempt instead of being hidden by the fallback. A rejected target is closed and the next one is tried; when none matches, the error names each target's observed role. `any` sends no probe at all. The probe uses `pg_catalog`-qualified names so a role-level `search_path` cannot shadow it. Open: the probe adds one round trip to every connection attempt for the non-`any` values, no live primary/standby pair has been measured, and switchover mid-upgrade, reconnect after a failover and the strict-role timeout path still need a real cluster.
- [ ] **F08 Text COPY input.** Test transaction-scoped streaming, constraints, interruption and pool reuse. Observe FILE and PIPE separately on LTS. Check bytes_total only for FROM FILE and record view permissions. Check that import works on older servers without the view.
  Partial, 2026-11-25 (commits 68021be, 63a1ac5). `CopyIn(tx, table, columns...)` streams rows into a transaction with `COPY ... FROM STDIN`: `Exec`/`ExecContext` append one text row (COPY text format: tab-separated, `\N` for NULL, `\t` `\n` `\r` `\v` `\b` `\f` `\\` escapes, values converted like other parameters), a call without values or `Close` sends CopyDone and reads the command result. The statement is not prepared server-side, so each row costs one CopyData frame and no Bind/Execute. The stream is pinned to the session that opened it, the row width is validated against the server's CopyInResponse, a binary-format response is refused by overall format and per column, and any server error is reported after the session is synchronized again so the pool can reuse it. A cancelled stream sends the protocol CancelRequest and returns the server's SQLSTATE with the session intact, and a statement on a session with an open stream is refused instead of interleaving with the CopyData frames. Independent review on 2026-11-25 found twelve issues; eleven are fixed with regression tests: COPY input is now accepted only on a transaction-pinned session (`ExecContext`/`QueryContext` direct callers are pointed to `CopyIn` and `ResetSession` discards a session with an open stream, so a pooled connection cannot be poisoned, F1); a client-side row failure sends CopyFail and resynchronizes, so `Close` no longer finishes a stream after a failed row (F2); options after `FROM STDIN` (CSV, HEADER, DELIMITER) are rejected because the encoder writes only the default text format (F3); a stream belongs to the statement that opened it (F4) and a finished statement cannot start another stream (F5); a send failure stops the stream's watcher and `conn.Close` stops an abandoned one (F6); a row call checks its own context and aborts the stream when it already ended (F7); per-column binary formats are refused (F8); the first command tag is kept when a trailing separator produces an empty statement, and its payload messages are tolerated (F9); the server-direction error messages now distinguish FROM STDIN, TO STDOUT and BOTH (F10); the row encoder reuses one buffer with a protocol size guard (F11). F12, a dotted name being interpreted as schema-qualified, stays documented in the `copyInSQL` contract. Local verification: full suite, `-count=5` on the new tests, `go vet`, golangci-lint 0 issues, gofmt clean, and a Linux/amd64 cross-build with CGO_ENABLED=0 on Go 1.27.4; `go test -race` cannot run in this environment (see F09). Open: COPY FROM FILE/PIPE views and their permissions are unobserved, large streams and very long rows are untested, COPY OUT, binary input and binary output stay with F14, and no live server has run an import yet.
- [ ] **F09 Notifications.** Test NOTICE separately from two-session LISTEN/NOTIFY. Cover registration commit, publisher rollback, UNLISTEN, reconnect and the thread-pool restriction.
  Partial, 2026-11-25 (commit 5b03cf2). `NewListener`/`NewListenerWithCallback` open one dedicated LISTEN session and expose `Listen`, `Unlisten`, `Notify`, `Ping`, `NotificationChannel`, `SetNoticeHandler` and `Close` under the upstream helper names. Commands are simple queries outside any transaction, so registration and delivery take effect at commit; channel names are quoted identifiers and payloads are `E''` literals. Notifications are delivered in server order, including one that arrives before the `LISTEN` result, through a ten-slot buffer that applies backpressure instead of dropping messages. After a connection failure the listener reconnects with exponential backoff between the caller's intervals, re-registers only channels whose `LISTEN` had been acknowledged (an unlistened channel is not re-registered), reports `ListenerEventDisconnected`/`ListenerEventReconnected`, and fails a command issued without a session instead of waiting for an unknown outage. A malformed notification discards the session; `Close` ends the session, closes the delivery channel and makes later commands return `ErrListenerClosed`; NOTICE messages reach the listening session's handler. Offline coverage is in `listener_test.go` against the scripted peer. `TestLiveNotifications` implements the live steps: a second session's committed NOTIFY, a listener's own `Notify`, rollback, commit and UNLISTEN. Live verification is still unavailable. Local verification: full suite, `-count=5` on the new tests, `go vet`, golangci-lint 0 issues, gofmt clean, and a Linux/amd64 cross-build with CGO_ENABLED=0 on Go 1.27.4. `go test -race` cannot run in this environment: every race binary, including one for an empty test module, exits with 0xc0000139 (STATUS_ENTRYPOINT_NOT_FOUND), so the earlier race claims still need a CI re-run. Open: two-session live delivery, rollback/commit, the 7.0 thread-pool restriction, long outages and silent peer loss, notices from pooled sessions (consumed and discarded by design), and the upstream `ListenerConn` API.
- [ ] **F10 Vector data.** Test parameter binding, scans, nearest-neighbor ordering, NULL and invalid dimensions against a 6.x extension and 7.x kernel types. Include an extension-absent database.

The official Go guide binds and reads vectors as text (`'[1,2,3]'`, or `[]byte` holding that text), which the existing unknown-OID text handling already round-trips; vector OID names, typed scans, NULL and invalid dimensions, nearest-neighbor ordering and an extension-absent database still need a live 6.x or 7.x server.
- [ ] **F11 Concurrent vector search.** Reuse the application pool, bound concurrency, pin settings to the correct session, preserve order and per-item failures, and release connections on cancellation.
  Partial, 2026-11-25 (commits 8c5c998, 2f1aa60). `ExecuteMultiSearch(ctx, db, query, args, scanParams, threadCount)` runs the query once per argument set on at most `threadCount` sessions taken from the caller's pool through `db.Conn`, capped by the argument count and by the pool's connection limit; the reference helper opened its own pools from a connection string, so this signature change is deliberate and documented. Every argument set must be non-empty, which keeps each query on the extended protocol so the server parses exactly one statement; the query must be one SELECT using a vector operator, and the local check understands SQL quoting, line comments ending at either newline form, and non-nested block comments (dollar-quoted bodies are not special-cased and the server remains the final authority). Each worker holds one session for all of its queries, applies the scan parameters with parameterized `pg_catalog.current_setting` and `pg_catalog.set_config`, and restores the previous values in reverse order before the session returns to the pool; when a restore fails the connection is closed immediately instead of being pooled with changed settings. One worker's settings never reach another session. Results keep the input order and report failures per item with SQLSTATE preserved; text values are strings, bytea values are `[]byte`, NULL is nil and a duplicate column name keeps the last value. The function-level error is reserved for invalid arguments (nil handles, non-SELECT, multi-statement or operator-free queries, empty argument sets, no argument sets, a non-positive thread count, an empty or unsupported parameter value). Canceling the context marks unfinished items with the context error or the server's cancellation error and releases the pinned sessions. A thread count above the free capacity waits for a session, so the caller bounds the context when it can hold every connection. Offline coverage is in `vector_test.go` against the scripted peer: ordering plus restore, a non-divisible split over two workers, the worker cap, settings pinned per worker, per-item errors with restoration, parameter-read failure, partial-setting restore, invalid arguments, cancellation of an in-flight query discarding its session, restore failure discarding the session, and the row value mapping for duplicate, NULL and bytea columns. `TestLiveMultiVectorSearch` implements the live steps: a vector table with three rows, two parallel searches with a scan setting on each session, and ordered nearest-neighbor results; it skips when the server has no vector type. Open: no live dataVec or kernel vector extension, no live measurement of scan settings, no comparison with the reference helper's error-map shape, and no live multi-vector retrieval timing.

- [ ] **F13 Protocol and edition research.** Investigate fully encrypted databases, logical replication, MySQL listeners and oGRAC separately. Record wire protocol, dependencies and feasibility in pure Go for each.
  Partial, 2026-11-25 (commit ca44fb6). Research recorded in [protocol-research.md](protocol-research.md) against the openGauss 7.0 documentation: the fully encrypted database encrypts on the client (`gsql -C` or JDBC `enable_ce=1`, localkms CMK/CEK, AEAD AES-CBC-HMAC-SHA256 or SM4-SM3, DETERMINISTIC or RANDOMIZED columns) with no documented wire-protocol change, and a non-CE client can read ciphertext but not insert into an encrypted table, so Go support would have to derive the client codec and key store from those clients and is not planned; logical decoding is exposed through SQL functions (`pg_create_logical_replication_slot` with the `mppdb_decoding` or `wal2json` plugin, `pg_logical_slot_get_changes`/`peek_changes`, `pg_drop_replication_slot`), only the primary creates or drops a slot, standby decoding needs `enable_slot_log=on`, and the existing `QueryContext` can call the functions, so only a polling helper is future work while the documented streaming client (`pg_recvlogical --start`) has no described replication-protocol messages and stays unverified; the dolphin plugin adds a MySQL-protocol listener on a separate port (`enable_dolphin_proto`, `dolphin_server_port`, a B-compatibility database, `set_native_password`; documented clients differ by release: JDBC and CLI 8.0.28 and below in 7.0-RC2, JDBC 5.1.47 and the CLI 5.7.26–5.7.42 in 6.0.0-RC1; TLS 1.2 only, no cursors or stored procedures), which stays out of scope because `go-sql-driver/mysql` already speaks that protocol to it; oGRAC is a shared-storage multi-writer cluster whose documented drivers are JDBC, C and ODBC and where any instance accepts writes, so it needs cluster-aware HA work (the `pg_is_in_recovery()` role probe and `target_session_attrs` do not describe its nodes) rather than protocol work, and it waits for a cluster. Open: no live server for any of the four areas, and the oGRAC connection protocol for this client is undocumented.
- [ ] **F14 COPY extensions.** Decide and record scope separately for text output, binary input and binary output. For each implemented path, test large streams, NULL, cancellation and recovery. List any remaining unsupported format.
  Partial, 2026-11-25 (commit fc51f22). Scope decision: text output is implemented now; binary input and binary output remain unsupported and are refused rather than guessed. Text output is read with `db.QueryContext(ctx, "COPY ... TO STDOUT")`: the driver sends it as a simple query, reads CopyOutResponse, CopyData, CopyDone, CommandComplete and ReadyForQuery itself, and returns a `*sql.Rows` whose columns are `column1`..`columnN` and whose values are strings with NULL as nil, because the COPY protocol carries no names or type OIDs. Rows may be split across CopyData frames and several rows may share one, so an incomplete line is buffered; an unterminated row above 64 MiB stops the stream. The frontend cannot end copy-out mode with CopyDone or CopyFail, so `Rows.Close` reads and discards the remaining data until ReadyForQuery, which keeps the transaction usable, and stopping the server early requires cancelling the context: the driver sends CancelRequest and reports the server's cancellation through `Next`/`Rows.Err`. A statement with parameters, an `Exec` call and a `Prepare` call are refused before the session is touched; a CSV/HEADER/other options clause is refused because only the default text format is decoded; a binary CopyOutResponse or a row the driver cannot decode is stopped with a cancel request and the remaining data is discarded; a row with the wrong field count or a truncated final line is an error; an unconfirmed cancel discards the connection because the late signal could abort a later statement. A server error that arrives mid-stream is reported with its SQLSTATE after the session is resynchronized, while `Close` only reports a failure to resynchronize. Detection is word-based, tracks parenthesis nesting, understands string literals including dollar-quoted ones, quoted identifiers and comments, and tolerates whitespace or comments between the keywords and after the clause, so a subquery, literal or table name containing the words cannot be misrouted. Offline coverage is in `copy_out_test.go` against the scripted peer: rows split across frames with NULLs and asynchronous messages, the full escape set, early close draining the rest, close before the first row, a binary response stopped by cancel, an unconfirmed cancel discarding the session, server errors before and during the stream, a truncated final row, parameter/Exec/Prepare refusals, a wrong field count, a multi-row frame above the row cap, the cap stopping the stream, cancellation of an in-flight copy with the session resynchronized, a trailing empty statement, and 500 rows streamed in seven-byte frames. Open: binary input, binary output, CSV and HEADER output, live large-table copy and timing, `COPY ... TO STDOUT` through the extended protocol, and a live server for any of these paths.
- [ ] **F15 Encodings and modes.** Inventory legal modes per build. On 7.0 LTS test A, B, C, PG and D as available, including B-mode dolphin requirements. Exercise non-ASCII text, raw bytea, NULL, non-UTF-8 server databases, and unsupported client encodings.
  Partial, 2026-11-25 (commit 96034f0). The client-text contract is enforced offline: the startup packet requests `client_encoding=UTF8`, every ParameterStatus is stored with the session's facts, a session that reports any client encoding other than UTF8 or SQL_ASCII is rejected at startup with a clear error, and a later ParameterStatus that changes the encoding marks the connection unusable with that error. The error is reported by the statement that consumed it (Exec or Query), by a streaming result that stops instead of decoding further rows, by `Rows.Close` while unread rows are discarded, by the closing call of a COPY IN stream, by a COPY OUT stream that is cancelled so the remaining copy data is never decoded, by transaction Commit/Rollback instead of `driver.ErrBadConn`, and by the listener as the disconnect cause; `sslmode=allow` does not replay the startup over TLS after the password reached the server. SQL_ASCII is accepted as raw byte passthrough because the server performs no conversion, and its text may not be valid UTF-8. All async handling sites now record ParameterStatus: exec, query, rows, prepare, close, both COPY directions, drain and the listener. Offline coverage is in `encoding_test.go`: the supported/rejected encoding table, the GBK startup rejection, the accepted SQL_ASCII startup and byte passthrough, a runtime `SET client_encoding TO 'GBK'` through Exec and through Query, a mid-stream SELECT and COPY OUT, `Rows.Close`, a transaction, the listener disconnect cause, the no-TLS-retry rule, and a round trip of non-ASCII text, raw bytea bytes that are not valid UTF-8, and NULL through both parameters and result columns. Open: live databases with a different server encoding, the A/B/C/PG/D modes and the dolphin prerequisite for B, server aliases such as `UNICODE` or `UTF-8` (never reported by a real server), and a live server for any of these paths.
